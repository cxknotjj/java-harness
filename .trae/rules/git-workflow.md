# Git 提交与推送规则（强制）

## 最高优先级：未经明示，禁止提交

- **严禁擅自执行** `git commit`、`git push`、`git add` 等任何会修改远端或有持久副作用的 Git 操作。
- **只有用户明确表述**「提交」「commit」「push」「推送」「上传到 GitHub/Gitee」等指令时，才允许执行 Git 提交类操作。
- 默认情况下，完成任务后**不主动提交、不主动推送**，只把成果展示给用户即可。
- 用户没有明确说提交时，即使代码已完成、已验证，也**不得**自行 commit 或 push。

## 执行提交时的规范

若用户明确要求提交/推送，遵循以下规范：

1. **先询问确认**：提交前先 `git status` / `git diff` 向用户简要说明将提交哪些文件，确认内容无误后再操作。
2. **忽略临时/生成文件**：`.mvn-repo/`（本地 Maven 仓库）、`.cli-history`、`target/`、IDE 本地配置（`.idea/`、`.vscode/`）等**绝不提交**。
3. **commit message**：使用英文（避免 Windows 下中文 commit 乱码），遵循 Conventional Commits 格式：
   - `feat:` 新功能
   - `fix:` 修复缺陷
   - `refactor:` 重构
   - `docs:` 文档
   - `chore:` 构建、工具、脚本等杂项
   - 正文说明"为什么"而非"做了什么"
4. **只提交明确在任内的文件**：不要用 `git add -A` 盲目添加；如用户有未明确的问题文件，先确认。
5. **推送前**：确认目标远程（origin / gitee），推送到是否正确的分支。

## 违反的后果

一旦未经授权提交/推送，属于严重越权操作，需立即向用户道歉并如实汇报哪些内容被提交、推到了哪里（无法直接撤销时需协助处理）。
